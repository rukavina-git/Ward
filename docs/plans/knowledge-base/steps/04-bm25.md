# 04 BM25 by hand

## Goal
Real keyword search over the chunks, written by hand: a tokenizer that
keeps OWASP IDs whole, an inverted index built in memory at load time,
and BM25 scoring, in packages/core. ID lookup stays first, so `id`
queries keep 1.0. Score it on the retrieval eval with textbook defaults
(before), tune a few knobs on dev only, then report dev and test (after).

## Do
1. Tokenizer `tokenize(text)` in `packages/core/src/tokenize.ts`:
   lower case; ID-shaped strings (`MASWE-0067`, `MASTG-TEST-0039`,
   `MASVS-NETWORK-1`) kept as one token; everything else split on
   anything that isn't a letter or digit; tokens of length 1 dropped. Two
   options, off by default, so their effect is measured: a short English
   stopword list (written in the file, ~100 words) and a light suffix
   stemmer (plural `s`, `ing`, `ed`, `ly`; hand-written, no Porter
   library). Rejected: splitting camelCase and dotted names
   (`setJavaScriptEnabled`, `android:debuggable`) now; noted as a dev-set
   experiment if the misses show it matters.
2. What gets indexed. Each chunk's searchable text is its record title,
   section path and text. Title and section can be weighted by repeating
   them (`titleWeight`, default 1). Placeholders are left out of search
   (lookup still finds them). Deprecated v1 tests stay searchable, since
   an agent may only know the old name. Demo code chunks (60% of the
   corpus, step 02 gotcha) get a `codeWeight` multiplier on their score,
   default 1, so dev can show whether they drown the prose.
3. BM25 in `packages/core/src/bm25.ts`: inverted index (token → chunk
   postings with term counts), document lengths, average length, IDF with
   the usual `+1` inside the log so it never goes negative, and the score
   with `k1` (default 1.2) and `b` (default 0.75). Built from the loaded
   index in memory when first used (2,132 chunks: milliseconds), not
   stored in the index file, so the file and its byte-identical build
   don't change. Deterministic: ties broken by chunk ID. Rejected: storing
   postings in index.json (bigger file, format change, no speed need).
4. `KnowledgeBase.search(query, { limit, ...options })` returns ranked
   chunks with record ID and score. IDs named in the query are looked up
   first (as `ids` does) and put on top; BM25 hits follow. A query with
   no known tokens returns an empty list, never a guess.
5. Eval. Add retrievers `bm25` (defaults: before) and `bm25-tuned`
   (chosen options: after) to `evals/src/retrieval.ts`. Tuning: a small
   grid on dev only (`k1` 0.9/1.2/1.5/2.0, `b` 0.5/0.75/0.9, stopwords
   and stemming on/off, `titleWeight` 1/2/3, `codeWeight` 1/0.5/0.25),
   picked by dev MRR, ties by recall@5. Print the grid's top 10 lines; the
   chosen settings go in core as named constants with a comment saying
   they came from dev. Test is scored once, for the final pick only. For
   `none` queries, record the top BM25 score, so plan 4 can decide on a
   "nothing relevant" cutoff; no cutoff in this step.
6. Tests (Vitest):
   - Tokenizer: IDs whole in mixed case and inside punctuation, splitting,
     stopwords and stemmer when on, empty input.
   - BM25 on a tiny hand-made corpus with hand-computed scores: rare word
     beats common word, repeated term saturates (k1), long document is
     penalised (b), term missing everywhere scores nothing, tie order.
   - `search`: named ID ranks first, placeholders never returned by text,
     empty and stopword-only queries return nothing, same query gives the
     same order.
   - Retrievers registered; tuned settings equal the core constants.

## Not in scope
- Vectors, embeddings and hybrid merge (step 05).
- A relevance cutoff for "nothing found" (plan 4, using the recorded
  scores).
- Search libraries (lunr, MiniSearch and similar): invariant.
- Changing queries, the split or expected IDs. If a query looks wrong,
  note it in progress.md; a query file change bumps its version and is
  a separate decision.
- Graph expansion of results (a weakness hit adding its tests): plan 4.

## Done when
- `npm run lint`, `npm run format:check`, `npm run typecheck` and
  `npm test` pass, and CI is green.
- `npm run eval:retrieval -- --retriever bm25` and `-- --retriever
  bm25-tuned` write their results. progress.md has dev and test recall@5
  and MRR, per origin, for ids, bm25 and bm25-tuned, and the chosen
  settings.
- `id` queries still score 1.0 on both splits.
- Glossary has: tokenizer, inverted index, IDF, term frequency
  saturation (k1), length normalisation (b), stopwords, stemming,
  hyperparameter tuning. Roadmap "BM25" ticked.
